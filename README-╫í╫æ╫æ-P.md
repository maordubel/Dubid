## ★ ההחלטה המרכזית: `live` נפרד מ-`published`

עד עכשיו היה דגל אחד — `published` — והוא ענה על שתי שאלות שונות:

* «האם מותר להראות מספרים?»
* «האם המספרים סופיים?»

זו הסיבה שהמוצר היה מת בין שבת לראשון. עכשיו:

```
פתוח                      →  אין ניקוד
נעול / המחזור בעיצומו     →  live  = true   ← ניקוד זורם, הטבלה זזה
"סיום מחזור"              →  final = true   ← ניקוד מקובע
```

`live` נגזר **בשרת** מ-`now() >= lock_at`, כלומר מאותה שורה בדיוק
שאוכפת את הנעילה. הוא לא תלוי בכך שמישהו יזכור ללחוץ "נעילה" בלוח
הניהול — וזה מכוון: כל דבר אחר היה מחזור נעול בפועל עם מסך ריק.

`published` נשאר בדיוק כפי שהיה, עם אותה משמעות. אף מסך קיים לא נשבר.

## ★ למה הניקוד החי הוגן

משחק שעדיין רץ נותן **נקודות אישיות** (דקות, שער, בישול), ולא נותן
**נקודות תוצאה** (ניצחון, שער נקי). זה לא באג — זו ההגדרה:
`core.v_team_match_results` מסנן `status = 'finished'`, ולכן ניצחון
לא נספר בדקה 20 ואי אפשר שיילקח בדקה 90.

התוצאה: המספר החי עולה, ולא קופץ למטה.

## ★ למה הסגירה ידנית ולא אוטומטית

"המשחק הסתיים" היא קביעה של ספק הדאטה, והוא טועה: משחק שנדחה, שורת
סטטיסטיקה שמגיעה באיחור, תיקון של שופט. סגירה אוטומטית הייתה מקבעת
ניקוד שגוי בדיוק ברגע שאין יותר מה לעשות איתו.

לכן: המערכת מציגה «6 מתוך 7 משחקים הסתיימו», **אתה** לוחץ.
ואם לחצת מוקדם מדי — יש "פתיחה מחדש", והפעולה נרשמת ביומן.

## ★★ מה אתה צריך לעשות ידנית ★★

### 1 · המסד — דקה

Supabase → **SQL Editor** → New query → להדביק את **כל**
`db/RUN-ALL.sql` → **Run**.

הקובץ כולל עכשיו גם את מיגרציה 24, והוא בטוח להרצה חוזרת.

> אם אתה מעדיף להדביק רק את החדש: `db/24_live_gameweek.sql` הוא
> קובץ עצמאי ואידמפוטנטי. **אבל** אז אל תריץ את `RUN-ALL.sql` הישן
> אחריו — הוא היה מחזיר את `game.results` לגרסה הקודמת.
> הכי בטוח: להדביק את ה-RUN-ALL החדש שמצורף כאן.

### 2 · הקוד

להעתיק את `src/`, `db/` ו-`scripts/` מהזיפ מעל הפרויקט, ולפרוס כרגיל.

### 3 · אין שלב 3

אין הגדרות חדשות, אין Edge Functions, אין מתגים בלוח הבקרה.

## בדיקה שזה עובד — 3 דקות

1. **לוח ניהול → מחזורים.** הכרטיס הראשון הוא עכשיו "המחזור החי",
   עם פס התקדמות וכפתור **סיום מחזור**.
2. **להזין תוצאה למשחק אחד** (משחק חי, לא "הסתיים").
3. **לפתוח את הדירוג בטאב שני.** תוך שניות הטבלה נפתחת עם פס
   «המחזור חי · X/Y משחקים הסתיימו · עודכן לפני…».
4. **ללחוץ על שורה בטבלה** → נפתח ההרכב של אותו משתתף, עם הנקודות
   ליד כל שחקן, וכפתור «השוואה להרכב שלי».
5. **מסך ההרכב שלי** → ליד כל שחקן מספר צהוב, ותגית «חי» למעלה.
6. **סיום מחזור** → התגית «חי» נעלמת, המספרים הופכים לזהב, והכרטיס
   מאבד את חותמת «לא סופי».

## שאלה אחת שדורשת החלטה שלך

**הדירוג עדיין מחושב בדפדפן** (`buildLeaderboard`), כולל בונוס
הנדירות ושוברי השוויון. זה עבד כשהדירוג נפתח פעם בשבוע; עכשיו הוא
נפתח כל הזמן, ו-200 מכשירים מחשבים את אותו דבר במקביל.

זה לא דחוף, וזה גם לא נכון להשאיר לאורך זמן: הברִיף אומר שכל כלל
תחרותי חייב להיות סמכותי בשרת. הצעה לסבב הבא — `game.leaderboard()`
שמחזירה שורות מדורגות מוכנות, והקליינט רק מצייר.

תגיד לי אם להיכנס לזה.
