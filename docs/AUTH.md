# DUBID · זהות והרשמה

**עודכן:** אוגוסט 2026 · **מקור:** `DUBIDAUTHSYNC.md`, מותאם לשני פרויקטים

## 0. שלוש דרכים להיות מישהו

```
  אורח            signInAnonymously        בלי טופס. ברירת המחדל.
  קוד חד־פעמי     access-code              אותו אורח, מכשיר אחר.
  חשבון           גוגל / אימייל+סיסמה      שורד ניקוי דפדפן.
  ─ ובנוסף ─
  אופסיידס        link-offsides            למי שכבר יש חשבון שם.
```

**אף אחת מהן אינה חובה.** אורח משחק מחזור שלם, מדורג, ומופיע
בטבלה בדיוק כמו כולם. הדגל `is_guest` משפיע רק על מה שהמוצר
*מציע* לו — לא על מה שמותר לו.

## 1. ⚠ ההבדל מול מסמך המקור

`DUBIDAUTHSYNC.md` נכתב תחת הנחה אחת גדולה:

> "פרויקט Supabase אחד ⇒ טבלת `auth.users` אחת. **אין מה לסנכרן**

**ההחלטה בפועל הייתה אחרת: שני פרויקטים נפרדים** (`docs/SUPABASE.md` §1).

| מהמסמך | תקף? | הערה |
|---|---|---|
| חוזה הטופס — `username`, `avatar`, `referred_by_code` | ✅ | מיושם ב-`AuthPanel.tsx` |
| `emailRedirectTo: window.location.origin` | ✅ | קריטי. ראו §3 |
| `detectSessionInUrl: true` | ✅ | כבר היה נכון ב-`supabase.ts` |
| `prompt: 'select_account'` בגוגל | ✅ | מיושם |

| פאץ' התנגשות שמות (§8) | ✅ | **וגם שופר** — ראו §5 |
| `auth.users` משותף | ❌ | אין. שני מסדים |
| לקוח OAuth יחיד שנותן אותו `auth.users.id` | ❌ | גוגל בדוביד יוצרת משתמש דוביד |

## 3. גוגל

**נקודה שמבלבלת כמעט את כולם:** גוגל לא מכירה את הדומיין של
האפליקציה. היא מכירה רק את Supabase. הזרימה היא

```
אפליקציה → גוגל → callback של Supabase → חזרה ל-origin של האפליקציה
```

**Google Cloud Console → Credentials → OAuth client ID (Web):**

| שדה | ערך |
|---|---|
| Authorized redirect URIs | `https://afxpjfxwpdjvlmuoawda.supabase.co/auth/v1/callback` — **רק זה** |
| Authorized JavaScript origins | `https://dubid.dubelteam.com` · `http://localhost:5173` |

הדומיין של האפליקציה **לא** נכנס ל-redirect URIs של גוגל אלא
לרשימת ה-Additional Redirect URLs של Supabase (§2).

> ⚠ **לאופסיידס נדרש לקוח נפרד**, כי ה-callback שלו מצביע
> לפרויקט אחר (`pqdzqpettxuuyngxbpxn`). זה ההבדל המעשי הגדול
> ביותר מול מסמך המקור, שהניח לקוח משותף אחד.

## 4. `emailRedirectTo` — למה זו לא שורה טכנית

**Site URL הוא שדה יחיד**, והוא ברירת המחדל לקישורים במיילים.
בלי `emailRedirectTo` מפורש, מייל אימות מחזיר תמיד לאותו מקום —
לא משנה מאיפה נשלח.

לכן שני המוצרים שולחים `window.location.origin` בכל קריאה, וזה
מיושם ב-`signUpWithEmail`.

### להחליט: אישור מייל דלוק או כבוי

| | דלוק | כבוי |
|---|---|---|
| חוויה | נרשם → יוצא לבדוק מייל → חוזר | נרשם → בפנים |
| הגנה | מונע חשבונות עם מייל מזויף | לא מונע |
| למחזור 2 | חיכוך מיותר לקבוצת ניסוי | **מומלץ** |

הקוד מטפל בשני המצבים: `signUpWithEmail` מחזיר
`needsEmailConfirmation`, והמסך מציג הודעת "שלחנו לך מייל" רק אם
צריך. אפשר להחליף את ההגדרה בכל רגע בלי לגעת בקוד.

## 5. ★★ התנגשות שמות משתמש — הבאג, והתיקון שהיה חסר ★★

### הבאג (מהמסמך, §8)

`username` הוא `UNIQUE`. כל מסלול שיוצר פרופיל בלי שם מפורש נופל
לגיבוי שנגזר מהמייל. המסמך שחזר:

```
info@alpha.com   id 4336d23f…  →  info_4336   ✓
info@beta.com    id 11111111…  →  info_1111   ✓
info@gamma.com   id 1111aaaa…  →  info_1111   ✗ duplicate key
```

ההרשמה השלישית **נכשלת ברמת השרת** — `Database error saving new user`.

### ★ מה שנמצא כאן, ולא במסמך

הפאץ' שהמסמך מציע גוזר סיומת מ**ארבעה** תווים של ה-UUID —
בדיוק אותו אורך כמו הגיבוי השבור שהוא בא לתקן.

הבדיקה שלנו (`db/tests/02_accounts.sql` §2) הריצה את התרחיש
המדויק מהמסמך מול הפאץ׳ שלנו, **ותפסה שהוא נופל**:

```
11111111-…  →  info_1111
1111aaaa-…  →  info_1111   ✗ duplicate key
```

זה אותו זוג UUID שהמסמך עצמו הביא כהוכחה לבאג. הפאץ' רק הזיז
אותו שלב אחד אחורה. ארבעה תווים הקסדצימליים הם 65,536 אפשרויות;
בפרדוקס יום ההולדת מספיקות כמה מאות הרשמות עם אותו חלק־מייל.

**התיקון אצלנו — שלוש דרגות, והשלישית לא יכולה להתנגש:**

```
1.  base                    פנוי → נשמר תו-בתו
2.  base_XXXXXXXX           שמונה תווים
3.  base_<32 תווים מלאים>   ה-UUID השלם = ייחודי בהגדרה
```

אין לולאה ("ספור עד שפנוי" הוא תחרות), אין ספירה, ואין תרחיש
שנופל.

> ⚠ **מי שמריץ את `patch-v18.9.453` בצד אופסיידס — לבדוק את אורך
> הסיומת שם.** אם היא ארבעה תווים, אותו באג ממתין.

### מה נמדד אצלנו

400 הרשמות מעורבות — גוגל בלי שם, שמות תפוסים, עברית, שם בן תו
אחד, רווחים בלבד:

```
users_total 406 · guests 0 · missing_username 0 · duplicate_usernames 0
```

והשמות בעברית שהיו פנויים נשמרו בדיוק:

```
אלוף
אלוף_D5598A59
מלך_הקרנות
מלך_הקרנות_33541B08
```

**אין סינון תווים.** מוצר שמדבר עברית ומכריח האנדל לטיני הוא
מוצר שלא מדבר עברית.

## 6. מה קורה בכל תרחיש

| תרחיש | ההתנהגות |
|---|---|
| אורח משחק ולא נרשם | עובד. מדורג. מופיע בטבלה |
| אורח נרשם | **אותה שורה.** `id` לא זז, ההרכבים לא זזים. דגל אחד משתנה |
| אורח מנפיק קוד ופודה במכשיר אחר | הזהות עוברת. `access-code` |
| נרשם בדוביד, יש לו גם חשבון אופסיידס | שני חשבונות נפרדים עד שהוא מקשר ב-`link-offsides` |
| נרשם באופסיידס בלבד | `link-offsides` — לא `signUp`. הרשמה תיצור חשבון שני |
| שם משתמש תפוס | הטופס חוסם מראש (`username_available`); ואם עבר — סיומת, לא שגיאה |
| יציאה מהחשבון | נוצר אורח חדש, לא מסך התחברות |

## 7. הדחיפה להירשם — הכלל

`src/lib/nudge.ts`, פונקציה טהורה עם בדיקות:

```ts
shouldNudge(ctx) = ctx.isGuest
                && ctx.dismissedForGameweek !== ctx.gameweekNumber
                && (ctx.hasSubmitted || ctx.published)
```

**מציעים רק למי שיש לו מה לאבד.** אורח שעוד לא בחר שחקן לא מסכן
כלום, והצעה באותו רגע היא מס כניסה — בדיוק מה שהמוצר החליט לא
לגבות.

ארבעה כללים שהופכים דחיפה לנימוס:

1. **סגירה אמיתית** — ה-× משתיק למחזור שלם, לא עד רענון.
2. **בלי מספרים מומצאים** — אין "12,000 נרשמו היום".
3. **שורה אחת** — אם צריך פסקה כדי להסביר למה כדאי, לא כדאי.
4. **אף פעם לא חוסמת** — רצועה בזרימה, לא מודאל.

## 8. צ'קליסט

**מסד:**

```sql
SELECT * FROM game.v_accounts_health;
-- missing_username = 0 · duplicate_usernames = 0

SELECT game.username_available('שם_שאף_אחד_לא_לקח');  -- true
SELECT game.suggest_username();                        -- שם פנוי
```

**ממשק:**

- [ ] אורח נכנס בלי טופס ומגיש הרכב
- [ ] אחרי ההגשה מופיעה ההצעה להירשם; × משתיק אותה למחזור
- [ ] גוגל → חוזר מחובר, ההרכב עדיין שם
- [ ] הרשמת אימייל → `game.users` מסומן `is_guest = false`
- [ ] מייל האימות מדוביד מחזיר **לדוביד**
- [ ] שם תפוס → הטופס חוסם לפני השליחה
- [ ] `?ref=CODE` ממלא קוד הפניה ומכריח מצב הרשמה
- [ ] יציאה → חוזרים לשחק כאורח, לא למסך נעול
