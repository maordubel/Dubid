# DUBID · הקליטה האוטומטית

מסמך הפעלה. נכתב אחרי `db/26_ingest.sql` ו-`db/27_cron.sql`.

## מה רץ, בלי שאף אחד נוגע

```
pg_cron כל 10 דק׳
   └─ game.ingest_tick()          ← שער SQL: יש בכלל מה לעשות?
        └─ Edge Function dubid-ingest
             ├─ SofaScore   (ראשי)     לוח · הרכבים · סטטיסטיקה
             ├─ 365scores   (גיבוי)    לוח · תוצאות · שמות בעברית
             ├─ הצלבה       אי־הסכמה על תוצאה = חסימה
             └─ game.ingest_snapshot()  ← נתיב הכתיבה היחיד
                  └─ game.auto_advance()
                       └─ dubid-score-gameweek  ואז  admin_set_published
```

המחזור נפתח לבד, ננעל לבד, מתנקד לבד ומתפרסם לבד. אדם נדרש
רק לשני דברים: למפות שחקן שהמערכת סירבה לנחש, ולשחרר התרעה.

## מתי המערכת עוצרת ומחכה

פרסום אוטומטי דורש **שלושה** תנאים יחד:

1. כל המשחקים במחזור `finished`
2. טביעת האצבע של הנתונים לא זזה `stable_minutes` (ברירת מחדל 45)
3. אין התרעה חוסמת פתוחה

התרעות חוסמות:

| סוג | למה זה חוסם |
|---|---|
| `unmapped_in_lineup` | מישהו בחר שחקן שאין לו נתונים — הוא יקבל 0 בלי סיבה |
| `var` | הספק לא אומר איזה שער בוטל. ניחוש משנה דירוג |
| `fixture_not_final` | משחק שנדחה או נזנח — אין תוצאה, ולא ממציאים אחת |
| `source_disagreement` | שני המקורות נתנו תוצאות שונות |

התרעות מתריעות בלבד: `card_rescinded`, `changed_after_publish`,
`source_down`, `unknown_event`.

## המיפוי — מה המערכת עושה ומה היא מסרבת לעשות

קובץ הסגלים מחזיק 457 שחקנים, **כולם בשם עברי בלבד**
(`name_en` = "TBD"), ו-101 מהם בלי מספר חולצה. לספק יש שם
לטיני ומספר. אין שדה משותף אחד שמספיק.

שלוש דרגות ביטחון, לפי סדר:

1. **מספר חולצה** בתוך הקבוצה — רק כשהוא יחיד בסגל
2. **שם מנורמל זהה** — עברית מול עברית, או לטינית מול לטינית
3. **דמיון שם** מעל 0.62 **וגם** פער של 0.12 מהמועמד הבא

מה שלא עבר — לא מנוחש. הוא עולה למסך «קליטה → מיפוי שחקנים»
עם עד שלושה מועמדים מדורגים, וקליק אחד סוגר אותו. מיפוי אחרי
המשחק עדיין תופס: הסריקה הבאה מכניסה את הנתונים שכבר נשמרו.

⚠ סף הדמיון שמרני בכוונה. **מיפוי שגוי נותן נקודות לשחקן הלא
נכון ואף אחד לא מבחין; חוסר מיפוי צועק.**

## פריסה של ה-Edge Function

**קובץ אחד. אחד.** `supabase/functions/dubid-ingest/index.ts`.

Edge Functions → `dubid-ingest` → `index.ts` → לסמן הכל → להדביק
→ Deploy. אין תיקיות, אין קבצים נוספים, אין ייבוא יחסי.

★ שתי פריסות נכשלו לפני שזו הייתה המסקנה:

| ניסיון | מה קרה |
|---|---|
| `./_lib/ingest/x.ts` | `Module not found` בזמן bundle — העורך לא יוצר תיקיות |
| שישה קבצים שטוחים | `500` בכל קריאה, **בלי שורה ביומן** — קובץ שלא נשמר נראה בדיוק כמו קובץ שנשמר |

הקובץ נבנה מ-`src/lib/ingest/*.ts` ומ-`_src/handler.ts` על ידי
`scripts/bundle-edge.mjs`, שגם נכשל מראש על התנגשות שמות בין
מודולים. מקור האמת לא זז.

`dubid-score-gameweek` נשארת עם `_lib/` — היא מייבאת שתי תיקיות
שיש בהן `types.ts` כפול.

## הבדיקה שמפרידה תקלת פריסה מתקלת ריצה

```sql
select net.http_post(
  url     := (select function_url from game.ingest_secrets where id),
  headers := jsonb_build_object('content-type','application/json',
                                'x-ingest-token',(select token from game.ingest_secrets where id)),
  body    := '{"phase":"ping"}'::jsonb);
```

ואז, אחרי כמה שניות:

```sql
select status_code, content from net._http_response order by created desc limit 1;
```

`200` עם `{"pong":true,...}` → הקובץ נטען והסודות קיימים; כל
תקלה שנשארה היא בהמשך המסלול.
`500` → הקובץ עצמו לא נטען. הסיבה ביומן ה-Edge Function.

`ping` לא נוגע ברשת ולא במסד, ולכן הוא לא יכול להיכשל מסיבה
אחרת. `version` בתשובה אומר איזו גרסה באמת פרוסה.

## מה לא נבנה (בכוונה)

* **סטטיסטיקה אישית מהמקור המשני.** מבנה הנתונים שלו לא אומת
  מול נתון אמיתי, ולנחש מבנה זה לכתוב נקודות שאיש לא בדק.
  תפקידו: לוח, תוצאות, שמות בעברית והצלבה.
* **xG.** אין בכיסוי של ליגת העל אצל אף אחד מהמקורות החינמיים.
* **פנדל שהוחמץ/נעצר** — נקלט רק כשהספק מסמן אותו במפורש.
  אחרת 0, ולא ניחוש.
