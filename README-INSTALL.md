# דוביד v8 — מה יש כאן

הקבצים מסודרים **בדיוק לפי מבנה הריפו**. לפרוס מעל הפרויקט ולדרוס.
רק קבצים שעבדתי עליהם בסבב הזה.

```
db/                    01, 05, 08 + תיקיית בדיקות SQL חדשה
dist-edge/             ★ להעתקה לריפו של אופסיידס
docs/                  מסמך הסנכרון + פילוסופיית העיצוב
public/brand/          הפרסומת לאופסיידס (PNG)
scripts/               סנכרון ויצוא Edge, מחולל הבאנר
src/                   קוד האפליקציה
supabase/functions/    הפונקציה, בשם חדש
tests/                 216 בדיקות (2 קבצים חדשים)
```

---

## ⚡ הדבר החוסם — תוקן

**לא ניתן היה לשלוח הרכב מהטלפון.**

`AppShell` במצב `fill` הסיר את הריפוד התחתון, מתוך הנחה ש"הילד
מנהל גובה בעצמו". אבל הניווט התחתון הוא `fixed bottom-0` — הוא לא
בזרימת המסמך, ואף אחד לא משאיר לו מקום מעצמו. כפתור "נעילת
ההרכב" ישב **מתחת** לניווט, והמסך לא נגלל כדי להגיע אליו.

עכשיו הריפוד זהה בשני הענפים — נוסחה אחת, לא שתיים.
`tests/shell.test.ts` תופס את זה אם יחזור; **בדקתי שהבדיקה נכשלת
על הקוד הישן**, לא רק עוברת על החדש.

## 1. SQL — מה חייבים להריץ מחדש

| קובץ | חובה? | למה |
|---|---|---|
| `db/05_gameweek_lock.sql` | **כן** | תיקון קריטי, ראו למטה |
| `db/08_offsides_coexistence.sql` | **כן** | חדש |
| `db/01_schema.sql` | לא חובה | תיקוני אידמפוטנטיות בלבד |
| `db/02,03,04,06,07` | לא | לא נגעתי |

### ★ הבאג שנמצא ב-`db/05` — והוא רציני

הרמתי PostgreSQL אמיתי והרצתי את כל המיגרציות. `game.submit_lineup`
— **נתיב הכתיבה היחיד של הרכבים** — קרס תמיד:

```
ERROR: record "v_player" has no field "position"
```

שתי עמודות בשמות לא נכונים: בשחקן העמודה היא `primary_position`
(לא `position`), ובסגל המחיר הוא `fantasy_price` (לא `price`).

**הנעילה עצמה עבדה מצוין.** הגשה אחרי הדדליין נדחתה בדיוק כמו
שצריך, ולכן כל בדיקה שמסתכלת רק על מקרה הכישלון הייתה עוברת.
אף הרכב תקין לא יכול היה להישמר בשרת.

עכשיו העמדה והמחיר נלקחים משורת הסגל הפעילה — וזה גם נכון יותר:
שחקן יכול לשחק בעמדה אחרת בקבוצה אחרת.

### מה נבדק, לא הונח

| # | מקרה | תוצאה |
|---|---|---|
| 1 | הגשה אחרי הדדליין | `DEADLINE_PASSED` ✓ |
| 2 | הרכב תקין לפני הדדליין | `submitted` ✓ |
| 3 | חמישה מאותה קבוצה | `one_player_per_team` ✓ |
| 4 | מחזור נעול בסטטוס | `GAMEWEEK_LOCKED` ✓ |

בנוסף: כל שמונת הקבצים רצו **שלוש פעמים ברצף** על מסד נקי. שלוש
הצהרות לא היו אידמפוטנטיות (`CREATE DOMAIN`, `CREATE TYPE`,
`CREATE TRIGGER`) — למרות שכתבתי לך שהן כן. תוקנו.

הבדיקות עצמן ב-`db/tests/`, עם הוראות הרצה.

## 2. Edge Function — הפתרון לריפו של אופסיידס

**הבעיה:** הפרויקט מחובר ל-GIT של אופסיידס. אינטגרציית ה-GIT
פורסת את `supabase/functions/` **של אותו ריפו**. הפונקציה של
דוביד לא הייתה שם, ולכן שום קריאה לא עבדה.

**הפתרון:** התיקייה `dist-edge/supabase/functions/dubid-score-gameweek/`
בחבילה הזו עומדת בפני עצמה לחלוטין.

```
להעתיק אותה אל  <offsides-repo>/supabase/functions/
git add . && git commit && git push
```

Supabase יפרוס אותה אוטומטית.

**השם השתנה** מ-`score-gameweek` ל-`dubid-score-gameweek`. בריפו
משותף שם גנרי הוא התנגשות שמחכה לקרות — לשני המוצרים יש ניקוד.
אף קליינט לא קרא לפונקציה, אז המעבר לא שובר כלום.

`npm run export:edge` מייצר את התיקייה מחדש, **ונכשל** אם מישהו
יוסיף ייבוא שיוצא ממנה. הבאג הזה כבר קרה פעמיים.

## 3. הלובי

השעון ירד מקופסה בגובה 92px למספר 36px — לפס אחד בגובה ~40px.
הכותרת ירדה ממגדל (באדג׳ 104px + כותרת + ברכה = ~300px) לשורה
אופקית אחת.

**התפנו כ-190 פיקסלים, וכולם הלכו לכפתורי המשחק.**

הנימוק: שעון הוא **מידע**, לא פעולה. הוא לא צריך להיות המספר הכי
גדול במסך. הפעולה היא שני הכפתורים.

## 4. הזירה — פיצ׳ר שהיה כתוב ובלי דרך להגיע אליו

`lib/leagues.ts` היה קיים במלואו: קודי הצטרפות, בדיקות, טבלה,
שיא ניצחונות, רצף — הכל בדוק. גם `db/06_private_leagues.sql`
במסד. **חסר היה רק מסך.** הלובי אפילו הצביע על "ליגות פרטיות",
והכפתור שלח לדירוג הכללי.

עכשיו יש `src/components/Arena.tsx` + `src/lib/leagueStore.ts`,
והזירה נכנסה לניווט התחתון.

בלי קופה ובלי פרסים — ניקוד בלבד, כמו שביקשת. תחושת הניצחון
מגיעה מהטבלה, מהמאזן ומהרצף.

"הכרטיס" ירד מהניווט והפך ליעד (מגיעים אליו מההרכב הנעול). פריט
ניווט קבוע למסך שרוב הזמן ריק הוא בזבוז של אחת מחמש משבצות.

## 5. אופסיידס — הפרסומת ותוכנית השיווק

### הפרסומת
`src/components/OffsidesBanner.tsx` — מעוצב בשפת "אור זרקורים"
(`docs/design/PHILOSOPHY-floodlight.md`): אלומה אחת, רשת נקודות,
צבע אחד לכל מצב, וסימן מקורי — דגל הקו של השופט עם שובל תנועה
שהוא ה-💨 בלי לצייר אמוג׳י.

בנוסף `public/brand/offsides-ad.png` (1200×628) — כרטיס השיתוף
לוואטסאפ ולרשתות. נוצר מ-`scripts/design/offsides-banner.py`.

### התוכנית
`src/lib/growth.ts` — **חמישה רגעים, לא באנר אחד:**

| רגע | מתי | הרעיון |
|---|---|---|
| `just-locked` | נעל הרכב, ההגשות פתוחות | לולאה פתוחה — הוא בדיוק השקיע והמערכת אמרה "תחכה" |
| `kickoff-soon` | פחות משעתיים לשריקה | הוא ממילא הולך לפתוח את המשחק |
| `beaten` | פורסמו תוצאות, לא ראשון | שנאת הפסד. בדוביד הריוונג׳ בעוד שבוע |
| `champion` | פורסמו תוצאות, ראשון | Peak-End. אתגר, לא נחמה |
| `idle` | ברירת מחדל | חשיפה שקטה |

**הצומת הוא הרגע, לא המסר.** דוביד הוא משחק שבועי; אחרי הנעילה
נשארים שלושה ימים ריקים. אופסיידס הוא בדיוק תשעים דקות, על אותם
משחקים שהוא ממילא יראה.

הגנות: אין אקראיות (אותו הקשר → אותו מסר, תמיד) · דחייה נשמרת
לכל המחזור · תקרה של 3 חשיפות לכל מסר · מקום אחד למסך.

שיוך: `?ref=dubid&src=<מסך>&v=<רגע>&gw=<מחזור>` — בלי שום מזהה
אישי, ויש בדיקה שמוודאת את זה.

16 בדיקות ב-`tests/growth.test.ts`.

## 7. עוד תיקונים במעבר על העמודים

- **הכותרת מדברת על המסך.** קודם היא הציגה "דוביד שוויצר" ומונה
  `3/11` בכל מסך — גם בחוקים, גם בדירוג. עכשיו שם המסך, והמונה
  רק כשבונים הרכב. בלובי אין כותרת בכלל (הוא כבר מציג לוגו ושעון).
- **`GameCard` נמחק.** 33 שורות קוד מת מאז שהלובי החליף את
  `HomeScreen`. גם `STATUS_ACTION` שנשאר תלוי באוויר.
- **`supabase/functions/_shared/` נמחקה.** שריד מהניסיון הראשון
  לפתור את באג ה-Edge. תיקייה כפולה שרק מבלבלת.
- **שוברי השוויון נכנסו למסך החוקים.** המנוע מכריע לפי שמונה
  רמות והדירוג אומר מה שבר את השוויון — אבל שום מקום לא הסביר
  מה ההיררכיה. משתמש שרואה "הוכרע לפי הקפטן" בלי הקשר חושב
  שהמצאנו משהו.
- **ההודעה במסך ההרכב** עוגנה ל-CTA (`bottom-full`) במקום מרחק
  קסם מתחתית המסך, שנשבר בכל שינוי גובה של הניווט.
