# דוביד · סבב I — כרטיס המנוי

רק מה שהשתנה או נוסף. מבנה התיקיות זהה: להעתיק מעל הקיים.

## ⚠ שני דברים שצריך לעשות בהגדרות — בלעדיהם חצי מהסבב לא עובד

### 1. Manual linking (חובה)
**Supabase → Authentication → Providers → Manual linking → הפעלה.**

בלעדיו אורח לא יכול להפוך לחשבון קבוע: `linkIdentity` נדחה,
והמשתמש נתקע. זה הדבר היחיד בסבב שאי אפשר לעשות מהקוד.

### 2. פריסת ה-Edge Function
```
supabase functions deploy access-code
```
בלעדיה אין `action: 'pass'`, וכפתור "קבלת הכרטיס שלי" יחזיר
שגיאה.

## ★★★ הבאג שתוקן — כדאי לקרוא ★★★

עד עכשיו, אורח שלחץ **"שמור את החשבון שלי"** קיבל חשבון **ריק**.

`supabase.auth.signUp()` על סשן אנונימי לא משדרג את המשתמש — הוא
יוצר משתמש חדש עם `uid` חדש. ההרכבים, שם הקבוצה והדירוג נשארו
תלויים על משתמש שאי אפשר להתחבר אליו יותר.

בשקט. בלי שגיאה. המשתמש ראה טבלה ריקה והסיק שהמערכת מחקה לו הכל.

תוקן ל-`updateUser` + `verifyOtp('email_change')` ול-
`linkIdentity` — אותו uid, אותה היסטוריה.

## מה חדש בשימוש

### לאורח
אחרי ההגשה הראשונה קופץ **כרטיס המנוי**: תמונה עם שם המאמן,
המפתח, ו-QR. ארבע פעולות — שמירה לגלריה, וואטסאפ לעצמי, שיתוף
(אינסטגרם/טלגרם/מייל), והעתקה.

הכרטיס זמין תמיד: **החשבון שלי → הכרטיס שלי**.

כדי לחזור: לסרוק את ה-QR, או להקליד את המפתח ב"יש לי קוד".

★ הכרטיס קופץ מעצמו **פעם אחת בלבד**. מסך מלא שחוזר כל מחזור
נקרא כהטרדה.

★ הנפקת כרטיס חדש **מבטלת את הישן**. המסך מזהיר לפני.

### לאדמין
לשונית חדשה — **משפך**:
```
נכנסו → שיחקו → שמרו כרטיס → השאירו מייל → נרשמו
```
ומתחתיה רשימת הלידים, עם תג «תזכורות» למי שאישר במפורש.

## למה המפתח באורך עשרה ולא שישה

הקוד הקיים (6 תווים, שעה, חד־פעמי) נשאר — הוא נכון ל"המכשיר
השני ביד עכשיו".

אבל בקשה לשמור תמונה ולשלוח אותה לעצמך היא הגדרה של **מפתח**:
משהו ששוכב בגלריה ועובד בעוד חודשיים. 6 תווים = 30 ביט, וזה
מספיק רק כשהם חיים שעה.

10 תווים = 50 ביט, יחד עם מכסה של עשרה ניסיונות לרבע שעה לכל
מנחש. מה שמגן הוא **האורך כפול המכסה**, לא אחד מהם לבדו.
